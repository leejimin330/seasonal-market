# 제철 장바구니 MVP 설계

2026-09-28 브레인스토밍에서 합의한 내용. 원래 기획서는 바탕화면의 `seasonal-market-plan.md`.

## 기획서에서 바뀐 것

| 항목 | 기획서 | 합의 |
|---|---|---|
| 유료 범위 | AI 추천·식단만 유료 | **가격 추이**와 **어디서 살까**가 유료(크레딧), 현재 가격·평년 대비는 무료 |
| 가격 출처 | KAMIS 오픈API | 공공데이터포털 aT 일별 도·소매 가격정보 (KAMIS는 기업 정보가 필요해 개인이 신청 불가) |
| 판매처 비교 | 없음 | aT 조사처별 가격을 유형(전통시장·대형마트 …)·지역별로 묶어 비교. 네이버 쇼핑 검색 API는 2026-07-31 종료돼 폐기 |
| AI 장보기 추천 | MVP 포함 | **2단계로 미룸** |
| 재화 | 플랫폼 공용 API | 이 서비스 안에서 자체 관리, `app/credits.py`만 갈아끼워 플랫폼으로 이전 |
| 크레딧 획득 | — | 가입 보너스 + 관리자 지급 (실제 결제 없음) |
| 도매 경락가 API | 사용 | MVP에서 제외 (주산지는 제철 표에 수기) |
| 구조 | — | 새 저장소, 헤아림과 같은 FastAPI + SQLite + 바닐라 JS |

## 크레딧 규칙

- 품목 1개 × 기능 1개를 결제하면 24시간 이용권. 이용권이 있으면 다시 차감하지 않는다.
- 가격: 가입 보너스 20, 추이 1, 어디서 살까 2 (`.env`에서 조정).
- 보여줄 데이터가 없으면(가격 기록·판매처 기록 없음) 404로 끝내고 차감하지 않는다.
- 차감은 "잔액 확인 → 차감 → 장부 → 이용권"을 트랜잭션 하나로. 동시에 눌러도 음수가 안 된다.
- 모든 변동은 `credit_ledger`에 남는다 (가입 보너스, 사용, 관리자 지급).
- 관리자 아이디는 `.env`의 `SEASONAL_ADMIN_USERS`. 계정은 CLI로만 만든다 (가입으로 선점 방지).

## 데이터

- `data/items.csv`: 품목 34개와 aT 조회 조건(부류·품목·허용 품종·등급·단위). 공식 코드표로 맞춤. 배추·무는 계절 품종(봄·고랭지·가을·월동)을 이어 붙이고, 한 날짜에 허용 품종이 여럿이면 조사처가 많은 품종만 쓴다. 수산물은 국산 생물/냉장 위주(꽃게는 연중 조사되는 냉동). 새우는 수입 흰다리만 조사돼 제외.
- `data/seasons.csv`: 제철 달, 주산지, 메모.
- 전국 평균 = 온라인을 뺀 조사처 가격의 평균 (aT가 전국 평균을 주지 않는다).
- 평년가 = KAMIS 정의대로 직접 계산: 지난 5년 같은 날짜(앞뒤 7일 평균) 중 최고·최저를 뺀 3년 평균, 3~4년치면 단순 평균.
- 수집: 처음엔 최근 400일, 이후 매일 05:00(KST) 마지막 날짜 7일 전부터. 이어서 품목마다 한 번 과거 5년치(평년가용).
- 판매처 유형: 조사처 이름(익명)으로 분류 — 전통시장, 대형마트("X-유통"·"X-마트" 포함), SSM·슈퍼, 백화점, 생협·전문점, 온라인. 2026-09 현재 소매 조사엔 전통시장과 대형마트만 나온다. 최근 30일치만 보관.
- 키가 없으면 샘플 데이터(`source=sample`)로 돌고 화면에 경고 띠가 뜬다. 키가 생기면 샘플 행을 지우고 실제 값으로 채운다.

## 오류 처리

- 가격 API 실패: 해당 품목만 건너뛰고 마지막 데이터 유지, 화면에 기준일 표시.
- 가격 기록이 없는 품목의 추이는 404 — 보여줄 게 없으면 돈을 받지 않는다.
- 로그인 실패는 IP당 5분 10회, 가입은 IP당 하루 3회로 제한.

## 2단계 후보

AI 장보기 추천 → 플랫폼 공용 인증·재화 API 연동 → 실제 결제 → 고정 도메인.
